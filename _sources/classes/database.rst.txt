Database files and generators
=============================

Source: ``src/radiation/database/``.

The database holds data only; no code reads it implicitly. A case names
the file it uses (``transitionFile`` of ``atomicLinesCoeffs`` or
``diatomicBandsCoeffs``, ``photoionisationFile`` of the continuum). What
the data are and where they come from: :doc:`/theory/database`.

Layout
------

.. code-block:: text

   database/
     README.md                 contents, conventions, checks, gaps
     SOURCES.md                one entry per source key (citation, DOI/URL, terms)
     atoms/
       N_I.dat  O_I.dat        neutral N and O: levels, E1 lines, Stark widths
       N_II.dat O_II.dat       N+ and O+: levels, E1 lines
       N_I_photoionisation.dat photoionisation cross section per level of N_I.dat
                               (Nahar and Pradhan 1997, NORAD)
       O_I_photoionisation.dat the same for O_I.dat (Nahar 1998, NORAD)
       *_photoionisation_Johnston2006.dat  former default (Johnston 2006 App. B)
     molecules/
       N2.dat                  X, A, B, C, a, b, b', c3, c'4, o3; 1P, 2P, 6 VUV systems
       N2plus.dat              X, A, B; first negative, Meinel
       NO.dat                  X, A, B, C, D, B', E; gamma, beta, delta, epsilon,
                               beta prime, gamma prime
       O2.dat                  X, B; Schumann-Runge
     sources/
       build_atomic_nist.py    fetch / johnston / build  -> atoms/<sp>.dat
       build_photoionisation.py fetch / build / check     -> atoms/*_photoionisation*.dat
       build_molecular.py      fetch / build / compare    -> molecules/*.dat
       johnston2006_stark.csv            Johnston (2006) Tables A-1 to A-4
       johnston2006_photoionisation.csv  Johnston (2006) Tables B-1 to B-4
       johnston2006_levelmodel.csv       Johnston (2006) Tables 3.1, 3.2
       huber_herzberg1979_constants.csv  Huber-Herzberg values used
       raw/                    NIST ASD responses, MANIFEST.json
       raw/molecules/          IPAC tables, PARADE N2ihl.dat, Laux (1993) CSVs,
                               IAEA data, MANIFEST.json

Every data file starts with a ``//`` provenance header (source keys,
query URLs, retrieval times, SHA256) and says "Generated by ... ; do not
edit". Both readers accept ``//`` comments: the atomic reader through the
OpenFOAM tokenizer, the molecular reader because comments sit between
blocks or after the values of a line.

Atomic format
-------------

Read by ``atomicLines::readTransitions`` (``IFstream >>``, free format):

.. code-block:: text

   nLevels
   g  E[cm^-1]  index  n  gaunt_bf                               (one row per level)
   nLines
   lambda_vac[A]  i_low  i_up  g_low  g_up  A_ul[s^-1]  w_Stark[A]  0   (one row per line)

.. list-table::
   :header-rows: 1
   :widths: 18 82

   * - Column
     - Meaning
   * - ``g``
     - statistical weight :math:`2J+1` of the level
   * - ``E``
     - level energy [cm\ :sup:`-1`] above the ground level
   * - ``index``
     - level label 1..nLevels (levels sorted by energy); lines refer to it,
       distribution files use it as the level identifier
   * - ``n``, ``gaunt_bf``
     - principal quantum number of the outermost orbital (derived from the
       ASD configuration) and a bound-free Gaunt factor (0, no source);
       read and not used by ``atomicLines``
   * - ``lambda_vac``
     - ASD Ritz vacuum wavelength [Å]
   * - ``i_low``, ``i_up``
     - level indices of the line; a line referring to an absent index is a
       fatal error
   * - ``g_low``, ``g_up``
     - weights given with the line
   * - ``A_ul``
     - Einstein coefficient [s\ :sup:`-1`]
   * - ``w_Stark``
     - Stark half width at half maximum [Å] at :math:`T_e = 10^4` K,
       :math:`n_e = 10^{16}` cm\ :sup:`-3` (0: no source)
   * - last column
     - read and discarded

Each line with a Stark width carries a comment such as
``// Stark: Johnston2006 Table A-2 p. 198 line 130 (src 1)``.

Photoionisation format
----------------------

Read by the continuum class ``boundFreePhysical`` (``crossSection
tabulated``; :doc:`continuum`):

.. code-block:: text

   nLevels
   index hydrogenic
   index steps  nSteps  hnuA_1 hnuB_1 sigma_1 ...     [eV eV Mb]
   index power  hnu_th sigma_th theta                 [eV Mb -]
   index bins   nBins  hnu_0 ... hnu_nBins  sigma_1 ... sigma_nBins  [eV Mb]

one row per level of the transition file (same index), 1 Mb =
10\ :sup:`-22` m\ :sup:`2`; each row has a comment naming its source
(the NORAD LS state and the ASD and NORAD binding energies, or the
Johnston group and table).

Molecular format
----------------

The PARADE layout, read by ``diatomicBands::readParade`` record by record
(the first token of each record; records starting with ``c`` are
comments):

.. code-block:: text

   [Version]           1 0 0 1 0 / date
   [Energy-Levels]     nStates 0 1 0 0 / one state name per line (ground state first)
   [band-<name>]       1 0 0 3 1 / upper index  lower index  type index  smf
   [<state>]           17 0 0 0 1 / 17 values, one per line
   [transition-<name>] nRows 0 0 0 5 / one header record starting with 'c' / rows

The 17 state values, in order: :math:`g_e`, :math:`T_e`, :math:`D_0`,
:math:`\omega_e`, :math:`\omega_e x_e`, :math:`\omega_e y_e`,
:math:`\omega_e z_e`, :math:`B_e`, :math:`\alpha_e`, :math:`\mu` [amu],
``nuspin``, ``altnat``, :math:`D_e`, :math:`\beta_e`, :math:`r_e` [cm],
:math:`A`, :math:`\Lambda` (energies in cm\ :sup:`-1`). A transition row is
:math:`v'`, :math:`v''`, :math:`R_e^2` [(e a\ :sub:`0`)\ :sup:`2`],
:math:`q_{v'v''}`, :math:`R_e^2 q` (the fifth column is not read):

.. code-block:: text

   [transition-N21p]
   406 0 0 0 5
   c vu vl sumre2/fcf FCF SRe2
   0 0 4.3134e-01 4.010e-01 1.7297e-01   // nu 9551.9 A 5.090e+04 A_rc 5.100e+04 Re 2.680e-01

State and band indices are 1-based in the file. The reader skips exactly
one record after the row count (the ``c`` header); the generators write
exactly one, so every row is read (``diatomicBands.H`` item 1). The log of
``diatomicBands`` reports per band the rows not read.

Generators
----------

All three scripts are run from ``database/sources``; their docstrings give
the full description.

``build_atomic_nist.py``
~~~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: bash

   python3 build_atomic_nist.py fetch                  # NIST ASD responses -> raw/
   python3 build_atomic_nist.py johnston <thesis.pdf>  # -> johnston2006_stark.csv
   python3 build_atomic_nist.py build                  # -> ../atoms/<spectrum>.dat

* ``fetch``: one levels query and one lines query per spectrum (N I, O I,
  N II, O II) and the ASD version-history page; existing raw files are
  never overwritten; 5 s pause between requests; URL, UTC time, size and
  SHA256 of every response in ``raw/MANIFEST.json``.
* ``johnston``: parses ``pdftotext -layout`` of the thesis into the Stark
  width table (one row per table row, with table and page).
* ``build`` (default): reads ``raw/`` and ``johnston2006_stark.csv`` only;
  refuses an air-wavelength response; writes the four atomic files.

``build_photoionisation.py``
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: bash

   python3 build_photoionisation.py fetch   # NORAD files -> raw/norad/ (MANIFEST.json)
   python3 build_photoionisation.py build   # -> ../atoms/N_I_photoionisation.dat, O_I_..., *_Johnston2006.dat
   python3 build_photoionisation.py check   # bin areas against the NORAD tables

Default files: reads the NORAD photoionisation and energy files of N I and
O I (Nahar and Pradhan 1997; Nahar 1998) and the ASD level files, assigns
every J-resolved ASD level to the LS state of the same parent term, outer
orbital and term (equivalent-electron levels by term), moves the table so
that every channel opens at the ASD binding energy and writes it as bins
(0.02 eV to 2 eV above threshold, 0.1 eV to 12 eV, 30 logarithmic bins
to the end), or ``hydrogenic`` without a state. Former files
(``*_Johnston2006.dat``): reads the Johnston level-model and cross-section
transcriptions and assigns every ASD level to a Johnston group (same
configuration and term; same outermost orbital, term and ion-core parent;
or the hydrogenic n-groups). The assignment table is in each file header.

``build_molecular.py``
~~~~~~~~~~~~~~~~~~~~~~

.. code-block:: bash

   python3 build_molecular.py fetch               # IPAC tables, Gilmore PDF, IAEA -> raw/molecules/
   DSMC_ROVIBRONIC_DIR=<checkout> \
       python3 build_molecular.py build           # -> ../molecules/*.dat
   python3 build_molecular.py compare <N2i.dat>   # N2 1P/2P against a PARADE N2 file

* ``build`` reads ``raw/molecules/`` and ``huber_herzberg1979_constants.csv``
  only (no network): IPAC tables for the main systems, the verbatim PARADE
  N2ihl file (SHA256 checked) for the N\ :sub:`2` VUV systems, the Laux
  (1993) transcriptions for NO :math:`\epsilon, \beta', \gamma'`. It needs
  ``DSMC_ROVIBRONIC_DIR`` (a DSMC_Rovibronic checkout) for ``NO.dat``,
  which reads the version-2 species database
  (``src/lagrangian/DSMC/speciesDatabase/v2/dsmcSpectroscopyTablesV2.C``),
  and stops with a message if it is not set. It prints the checks of the
  README (same state in two tables, IPAC against Gilmore, band origins).
* ``compare`` prints a band-by-band comparison of the N\ :sub:`2` first
  and second positive systems with a PARADE N2 file (read only).

Files kept off git (``database/.gitignore``):
``sources/raw/molecules/Gilmore1992_JPCRD21_1005.pdf`` and
``sources/raw/molecules/IPAC_*``; ``fetch`` retrieves them and the hashes
of ``MANIFEST.json`` check them.

After a change of ``atoms/``, regenerate the level maps and multiplet
tables of the dsmcFoam radiation coupling in the DSMC_Rovibronic
repository (``src/lagrangian/DSMC/radiationCoupling/database/sources/``,
with ``RADIATIONFOAM_DIR`` pointing to this checkout).
