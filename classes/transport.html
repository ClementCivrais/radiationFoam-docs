Transport classes

Source: src/radiation/transport/.

transport/
    basic/radiationTransportModel/   abstract base, run-time selection (entry mode)
    derived/singleCell/              one cell state, no transfer
    derived/shockTube1D/             1-D shock-tube profile, slab across the tube

The physics is in Radiative transfer. A transport model reads its own sub-dictionaries of system/radiationProperties, computes the spectral coefficients cell by cell, transfers the radiation and writes its outputs to postProcessing/radiationFoam/.

radiationTransportModel

Abstract base class (basic/radiationTransportModel/radiationTransportModel.H). It holds references to the objects built by the application radiationFoam: the Time of the case, the radiationProperties dictionary, the radiating species (Radiating species), the population model (Population models) and the continuum processes (Continuum classes). One pure virtual function:

//- Compute the spectra, transfer the radiation, write the outputs
virtual void solve() = 0;

Run-time selection: radiationTransportModel::New reads the word entry mode of radiationProperties:

Type

Default

Meaning

singleCell or shockTube1D

The other top-level entries read by the application are species, populationModel and continuum (Input Reference).

singleCell

derived/singleCell. Selection name singleCell. One cell state, the spectral emission and absorption on one grid, no transfer and no mesh.

mode            singleCell;
populationModel boltzmannTemperatures;  // or cellDistribution
spectralGrid    { minWavelength 700; maxWavelength 900; nPoints 80001; }
species         { N { ... } }
cellState
{
    electronNumberDensity   1e22;       // [m^-3]
    electronTemperature     10000;      // [K]
    // distributionFile "<constant>/radiation/cellDistribution";
    species
    {
        N
        {
            numberDensity               1e22;   // [m^-3]
            translationalTemperature    10000;  // [K]
            electronicTemperature       10000;  // [K]
            // vibrationalTemperature, rotationalTemperature: diatomics
        }
    }
}

The temperatures are those of the boltzmannTemperatures population model (a Boltzmann re-expansion over the levels, Level populations).

Outputs (postProcessing/radiationFoam/):

  • spectrum.csv: wavelength [nm], emission_coefficient [W m-3 sr-1 m-1], absorption_coefficient [m-1], 17 digits;

  • populations_<species>.csv: key, g, energy [J], number_density [m-3] of every level;

  • continuum.csv: only with an active continuum, the emission and absorption of each process.

The log gives, per species and continuum process, \(4\pi\int j\,\mathrm{d}\lambda\) [W m-3] and \(\int\kappa\,\mathrm{d}\lambda\) [m-1 m] over the window. Worked cases: singleCell_N: one cell of atomic nitrogen, singleCell_O: one cell of atomic oxygen.

shockTube1D

derived/shockTube1D. Selection name shockTube1D. The cells of a 1-D shock-tube profile, each an independent uniform slab of thickness diameter; radiance \(I_\lambda = -(j_\lambda/\kappa_\lambda)\,\mathrm{expm1}(-\kappa_\lambda D)\) (\(j_\lambda D\) if \(\kappa_\lambda = 0\)). The line data of every species are built once at start-up; per cell only the populations, widths and line placement are computed.

mode            shockTube1D;
populationModel boltzmannTemperatures;      // or cellDistribution
species { N2 { ... } N { ... } O { ... } }
shockTube1DCoeffs
{
    diameter        0.1016;                 // [m], EAST 4-inch tube
    windows
    {
        IR  { minWavelength 740; maxWavelength 880; nPoints 14001; }
        VUV { minWavelength 140; maxWavelength 180; nPoints 8001; }
    }
    bands                                   // [nm]
    {
        NI_868      (861 872);
        NI_149      (148.5 150.5);
    }
    profile
    {
        source      macroFile;
        file        "<case>/constant/profile.csv";
    }
    writeSpectra        none;
}

Keyword

Cell numbering: without distribution, \(k\) is the index of the profile cell sorted by \(x\) (0 to \(N-1\)); with it, \(k\) is the index of the distribution file, and only the listed cells are computed. The lists of writeSpectra and writeDistributions refer to these \(k\).

Instrument cameras: each sub-dictionary of instrument names its window (optional when there is one window) and an optional wavelengthRange (a b) [nm]; the radiance on that range is copied for every cell and the measurement model is applied after the cell loop. The camera keywords handled by shockTube1D itself are distanceUnit (m, default; cm; mm), spatialBinWidth (optional, in distanceUnit: the raw radiance is averaged over uniform bins in \(x\), weighted by the cell widths), metricHalfWidth (default 0.02 m), shockFront (position, or band (default: the first camera band) with criterion (default peakRadiance); upstreamSide low (default) or high), spectra and writeField (default false). Their meaning and the instrument functions are documented in Instrument classes and Instrument model: reproducing a shock-tube measurement.

Outputs (postProcessing/radiationFoam/):

  • bands.csv: per cell \(k\), x [m] and the radiance integrated over each band and each whole window [W m-2 sr-1] (rectangle rule on the grid points, a point on a band edge inside the band); the header gives the grid index range of each band;

  • profile.csv: the cell states used (n_e, T_e, and n, Ttrans, Trot, Tvib, Telec per species) and emission_<window>, \(4\pi\sum_i j_i\,\Delta\lambda\) [W m-3];

  • spectra_<window>.bin and .info: radiance spectra of the writeSpectra cells, float64 in the byte order of the machine, one row of nPoints values per cell; the .info file gives the grid, the byte order and the rows (row, \(k\), \(x\));

  • with writeCoefficients: emission_<window>.bin and absorption_<window>.bin, same layout;

  • with writeDistributions: distribution/cell<k> (and the index distribution/cells), the level populations of the population model in the format of dsmcRadiationDistribution (17 digits), so a Boltzmann profile can be replayed through cellDistribution;

  • with instrument: instrument_<camera>_bands.csv, instrument_<camera>_spectra.csv and, with writeField, instrument_<camera>_field.bin (Instrument classes).

The log reports the CPU time per cell. Reading the binary files is described in Post-processing; worked cases are shockTube1D: radiance along a 1-D post-shock profile and EAST shot 50-29 on a dsmcFoam run.
